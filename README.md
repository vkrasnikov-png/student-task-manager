# Student Task Manager

Вебзастосунок для планування навчального навантаження, контролю дедлайнів та організації виконання практичних і лабораторних робіт студентів.

## Цільовий користувач
Студенти закладів вищої освіти, які одночасно опановують кілька навчальних дисциплін та потребують зручного інструменту для обліку завдань і контролю термінів їх здачі.

## Проблема, яку розв’язує продукт
Накопичення навчальних завдань із різних предметів у розрізнених джерелах (нотатках, месенджерах, електронних кабінетах) призводить до втрати пріоритетів, пропуску дедлайнів та нерівномірного розподілу навантаження протягом семестру.

## Мета продукту
Створити єдиний структурований простір для фіксації навчальних завдань, відстеження статусу їх виконання та своєчасного планування підготовки до заліків і екзаменів.

## Початковий план створення продукту

### Проблема
Студенти закладів вищої освіти фіксують завдання з різних навчальних дисциплін у розрізнених нотатках, месенджерах та електронних кабінетах, через що втрачають контроль над пріоритетами та ризикують пропустити терміни здачі лабораторних і практичних робіт.

### Основний користувач
Студент бакалаврату, який одночасно вивчає декілька дисциплін і потребує єдиного структурованого простору для відстеження навчальних завдань та дедлайнів.

### Мета продукту
Мета продукту — допомогти студенту систематизувати навчальні завдання за дисциплінами, контролювати терміни їх виконання та рівномірно розподіляти навантаження протягом семестру.

### Очікуваний результат
Після входу до системи студент бачить актуальний перелік своїх навчальних завдань із прив’язкою до конкретних дисциплін, термінами здачі, рівнем пріоритету та поточним статусом виконання.

### Етапи створення продукту
1. Проаналізувати труднощі обліку навчальних робіт у студентів та зафіксувати основну проблему й цільову аудиторію.
2. Визначити базовий набір функцій для Student Task Manager: створення завдання, вибір дисципліни, встановлення дедлайну, зміна статусу та видалення запису.
3. Сформувати функціональні та нефункціональні вимоги до інтерфейсу, мови, швидкодії та збереження навчальних даних.
4. Спроєктувати структуру застосунку (головна панель зі списком завдань, форма додавання роботи, фільтрація за предметами) та визначити ключові сутності: користувач, дисципліна, завдання, дедлайн і статус.
5. Розробити інтерактивний прототип основних екранів для перевірки зручності додавання та перегляду навчальних завдань.
6. Реалізувати програмну версію ключових функцій обліку завдань, збереження даних та оновлення статусів виконання.
7. Провести тестування роботи системи на коректні й некоректні сценарії введення (порожні обов’язкові поля, некоректна дата дедлайну, зміна статусу та відображення на різних екранах).
8. Оновити документацію в репозиторії (`README.md`) та додати інструкцію із запуску й використання застосунку.
9. Перевірити стан репозиторію, підготувати коротку презентацію проєкту та продемонструвати основний сценарій роботи студента із завданнями.
