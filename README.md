# React + Vite

This template provides a minimal setup to get React working in Vite with HMR and some Oxlint rules.

Currently, two official plugins are available:

- [@vitejs/plugin-react](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react) uses [Oxc](https://oxc.rs)
- [@vitejs/plugin-react-swc](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react-swc) uses [SWC](https://swc.rs/)

## React Compiler

The React Compiler is not enabled on this template because of its impact on dev & build performances. To add it, see [this documentation](https://react.dev/learn/react-compiler/installation).

## Expanding the Oxlint configuration

If you are developing a production application, we recommend using TypeScript with type-aware lint rules enabled. Check out the [TS template](https://github.com/vitejs/vite/tree/main/packages/create-vite/template-react-ts) for information on how to integrate TypeScript and Oxlint's TypeScript related rules in your project.

# Вимоги до програмного продукту

## Загальна інформація

**Назва продукту:** Student Task Manager.

**Короткий опис:** вебзастосунок для обліку навчальних завдань, керування статусами виконання та контролю дедлайнів за дисциплінами.

# Перевірка вимог програмного продукту

## Загальна інформація

**Назва продукту:** Student Task Manager.

**Файл із вимогами:** [requirements.md](requirements.md)

**Кількість функціональних вимог:** 5.

### План розробки
1. Уточнити вимоги студентів до обліку завдань і сформувати пріоритетний список функцій.
2. Спроєктувати структуру даних (дисципліна, завдання, дедлайн, статус) і створити прототип основних екранів.
3. Реалізувати першу робочу частину продукту — форму створення завдання та відображення загального списку робіт.
4. Перевірити роботу базового сценарію на коректні й порожні поля та зібрати перші відгуки від одногрупників.
5. Додати наступну групу функцій з урахуванням отриманих зауважень: зміну статусу виконання, прив’язку до дисциплін і фільтрацію за строками здачі.
6. Провести комплексну перевірку інтерфейсу та логіки роботи, виправивши виявлені помилки й незручності.
7. Оновити документацію в README.md, підготувати коротку презентацію та провести демонстрацію готового продукту.
